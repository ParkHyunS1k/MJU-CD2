# 성인병 위험 예측 모델 재설계

- 작성일: 2026-10-12
- 상태: 검토 대기
- 범위: ① 학습·평가 파이프라인(`training/`), ② 백엔드 예측 서비스(`app/services/prediction_service.py`)
- 범위 밖: ③ 가족력·키 저장(Supabase `users` 칼럼, `/users/me` 스키마), ④ 모바일 입력 화면. 별도 설계로 진행한다.

## 1. 배경과 목표

현재 배포 모델(`models/*.pkl` 7개, `training/retrain_final.py`)은 SMOTE + 로지스틱 회귀 4개(고혈압 남·여, 당뇨 여, 중성지방 여)와 SMOTE + ExtraTrees 3개(콜레스테롤 통합, 당뇨 남, 중성지방 남)를 섞어 쓴다. 입력은 나이·체지방률·사지근육합이다. 설명은 `shap`의 LinearExplainer와 TreeExplainer로 만든다. 이 모델에는 다음 문제가 있다.

| 문제 | 내용 |
|---|---|
| 고혈압 라벨 오류 | `HE_HP >= 3`이라 고혈압 전단계(130–139/80–89)가 양성에 포함된다. 유병률이 36%가 아니라 51%로 잡힌다 |
| 당뇨 라벨 누락 | 공복혈당·당화혈색소 수치만 봐서, 약으로 조절 중인 환자가 음성이 된다 |
| 입력 정의 불일치 | 학습 피처 `SMM`은 사지 4부위 근육량 합인데, 앱은 인바디 "골격근량"을 넣는다. 서로 다른 값이다 |
| 확률 왜곡 | SMOTE를 쓰면 예측 확률이 실제 유병률의 약 5배로 부푼다 |
| 기준값 과적합 | 위험 등급 기준값을 학습 데이터 자체의 예측값으로 정한다 |
| 데이터 포함 | pkl 안의 SMOTE 객체에 KNHANES 참가자 행(최대 4,439행)이 저장돼 있다 |

**목표**
- 앱 타겟층(30대 전후의 성인병 초기 위험군)에서 보정된 절대 위험 확률과 기여 요인을 제공한다.
- 입력은 InBody 270 결과지에서 얻을 수 있는 값과 사용자 프로필로 한정한다.
- 평가는 기준값과 무관한 지표, 사전에 정한 통과 기준, 외부 데이터로 한다.

**비목표**
- 미래 발병 예측. KNHANES는 단면 조사라서 "현재 유병 상태"만 분류한다.
- 50대 이상 사용자에 대한 성능 최적화.
- 생활습관(흡연·음주·운동) 입력.

## 3. 데이터·라벨·입력

### 3.1 데이터

- 학습: 국민건강영양조사(KNHANES) 2022–2024 원자료(`training/data/hn22~24_all.sas7bdat`, Git 제외).
- 대상: 체성분검사 참여자(`BIA_ex == 1`), 만 19–59세.
- 2024년은 체성분검사를 40세 이상만 했다. 그래서 40세 미만은 2022–2023년 자료뿐이다.
- 라벨 또는 입력이 결측인 사람은 해당 질환 학습에서만 제외한다. 입력 결측률은 1% 미만이다.

질환별 표본 수(n / 양성)는 다음과 같다.

| 질환 | 19–59세 (학습) | 25–44세 (기준값·주 평가) | 30–39세 |
|---|---|---|---|
| 고혈압 | 7,415 / 1,441 | 2,921 / 261 | 1,142 / 74 |
| 당뇨 | 7,155 / 608 | 2,843 / 101 | 1,106 / 29 |
| 고콜레스테롤 | 7,169 / 1,697 | 2,849 / 361 | 1,108 / 124 |
| 고중성지방 | 6,426 / 796 | 2,549 / 302 | 990 / 114 |

### 3.2 라벨

| 질환 | 정의 | 기존 대비 |
|---|---|---|
| 고혈압 | `HE_HP == 4` (측정 140/90 이상 또는 혈압약 복용) | 전단계(`HE_HP == 3`)를 제외한다 |
| 당뇨 | `HE_DM_HbA1c == 3` (공복혈당 126·당화혈색소 6.5 이상, 의사진단, 약·인슐린 치료 포함) | 치료 중인 환자를 포함한다 |
| 고콜레스테롤 | `HE_HCHOL == 1` (총콜레스테롤 240 이상 또는 약 복용) | 같다 |
| 고중성지방 | `HE_HTG == 1` (12시간 이상 공복자 중 200 이상) | 같다 |

### 3.3 입력 변수

| 변수(앱 필드명) | 한국어 이름 | KNHANES | 앱 출처 |
|---|---|---|---|
| `age` | 나이 | `age` | 현재 연도 − 프로필 `birth_year` |
| `female` | 성별 | `sex == 2` | 프로필 `gender == "female"` |
| `bmi` | BMI | `HE_BMI` | 인바디 기록 `bmi` |
| `body_fat_percentage` | 체지방률 | `BIA_PBF` | 인바디 기록 `body_fat_percentage` |
| `fh_hypertension` | 고혈압 가족력 | `HE_HPfh1~3` 중 하나라도 1 | 프로필(③에서 추가). 없으면 0 |
| `fh_diabetes` | 당뇨 가족력 | `HE_DMfh1~3` | 위와 같다 |
| `fh_dyslipidemia` | 고지혈증 가족력 | `HE_HLfh1~3` | 위와 같다 |

가족력은 부·모·형제자매 중 한 명이라도 진단받았으면 1이다. KNHANES의 "모름(9)"·"비해당(8)"은 0으로 둔다. 앱의 "아니오"·"모름"도 0으로 넣는다. 네 질환 모델 모두 같은 7개 입력을 쓴다.

### 3.4 입력 선정 기준과 근거

후보는 다음 순서로 걸렀다.

1. **InBody 270 결과지와 KNHANES 양쪽에 있는 값일 것.** InBody 270은 부위별 근육을 판정 글자(표준 등)로만 표시하고 ECW비가 없다. 그래서 사지근육량과 ECW비는 제외했다. 골격근량은 KNHANES에 몸통 근육 변수가 없어 재현할 수 없다. 내장지방 레벨과 복부지방률은 KNHANES에 없다.
2. **VIF 5 미만일 것.**
3. **계수 부호가 의학 상식과 맞을 것.** 계수로 사용자 설명을 만들기 때문이다.
4. **위 조건을 통과한 조합 중 25–44세 AUROC·Brier가 가장 좋을 것.** 차이가 무작위 변동 범위 안이면 변수가 적고 결과지에서 바로 보이는 값을 고른다.
5. **설문 변수는 AUROC 증가와 역인과 여부를 함께 본다.**

체성분 조합 비교(19–59세 학습, 25–44세 5-fold CV)는 다음과 같다.

| 조합 | 체성분 VIF | AUROC 고혈압/당뇨/콜레스테롤/중성지방 | 계수 부호 |
|---|---|---|---|
| BMI·체지방률·체지방량·제지방량 | 10.1 / 25.9 / 30.3 / 14.3 | 0.802 / 0.832 / 0.696 / 0.795 | 체지방량이 음수(고혈압 −0.59, 중성지방 −1.12) |
| **BMI + 체지방률 (채택)** | 2.8 / 3.7 | 0.804 / 0.832 / 0.696 / 0.791 | 고혈압의 체지방률 −0.04(사실상 0), 나머지 양수 |
| 체지방량지수 + 제지방량지수 | 1.7 / 3.2 | 0.804 / 0.831 / 0.693 / 0.788 | 모두 0 이상 |
| BMI만 | 1.1 | 0.805 / 0.834 / 0.688 / 0.786 | 해당 없음 |

BMI + 체지방률을 채택했다. 성능이 4개 조합과 같고, 두 값 모두 사용자가 결과지에서 직접 보며 `trend_service`가 이미 추적하는 값이다. 고혈압과 당뇨에서는 BMI 단독과 성능 차이가 없다. 체지방률의 추가 기여는 고콜레스테롤(+0.008)과 고중성지방(+0.005)에서만 보였다. 평가 보고서에 이 사실을 그대로 적는다.

설문 변수 비교(전 연령 5-fold CV, 결과지 4개 체성분 기준 대비 AUROC 증가)는 다음과 같다.

| 추가 변수 | 고혈압 | 당뇨 | 고콜레스테롤 | 고중성지방 |
|---|---|---|---|---|
| 가족력 3개 | +0.015 | +0.039 | +0.015 | +0.001 |
| 흡연 | 0.000 | +0.002 | 0.000 | +0.012 |
| 음주 | +0.003 | +0.002 | +0.001 | +0.014 |
| 신체활동·스트레스 | ≤ +0.004 | | | |

가족력만 채택했다. 흡연·음주·운동은 진단 뒤에 바뀐 생활습관이 섞여 있다. 그 결과 계수 방향이 뒤집힌다(당뇨 모델에서 음주 빈도 −0.19). 이 계수가 기여 요인 설명에 그대로 노출되므로 제외했다.

**ML 밖에서 쓰는 값**: 내장지방 레벨과 복부지방률은 결과지에 인쇄된 InBody 기준(내장지방 10 이상 높음, 복부지방률 남 0.90 이상)으로 규칙 판정해 리포트에 넘긴다. 이는 RAG 리포트 쪽 작업이며 이 설계의 구현 범위가 아니다.

## 4. 학습

### 4.1 모델

- 질환마다 `Pipeline([StandardScaler, LogisticRegression(C=1.0, max_iter=2000)])` 하나를 만든다. `random_state=42`로 고정한다.
- 학습 데이터는 19–59세 전원이다. 60세 이상을 빼면 30대 보정이 좋아진다. 예측 평균/실제 비율은 당뇨 4.2%/2.6%에서 2.9%/2.6%로, 고콜레스테롤 14.8%/11.2%에서 10.5%/11.2%로 바뀐다. 고콜레스테롤의 30대 AUROC도 0.628에서 0.679로 오른다.
- 성별은 변수로 넣는다. 성별 분리 모델과 비교해 AUROC 차이는 +0.000~0.007이다.
- **데이터 증강(SMOTE, 클래스 가중치)은 쓰지 않는다.** 25–44세에서 AUROC는 같았지만(당뇨 0.832/0.831/0.835) 예측 평균이 실제 3.6%에서 19.9~21.3%로 부풀었다. 절대 확률을 보여주는 설계와 맞지 않는다.
- 기본 모델로 로지스틱 회귀를 고른 기준은 중요도 순으로 다음과 같다.
  1. **판별력**: 다른 모델과 같은 수준이다.
  2. **보정**: 절대 확률을 보여주므로 가장 중요하다. 로지스틱 회귀는 별도 보정 없이 보정 기울기가 1에 가깝다.
  3. **설명**: 기여도가 `계수 × (값 − 평균)`으로 정확하다. 변수의 작용 방향이 모든 사용자에게 같다.
  4. **적은 양성 수에서의 안정성**: 추정할 값이 8개뿐이다.
  5. **운영**: 모델 파일이 수 KB이고 `shap` 의존성이 필요 없다.
- 최종 입력 7개, 19–59세 학습, 25–44세 비중첩 5-fold CV로 비교한 결과는 다음과 같다(네 질환 평균).

  | 모델 | AUROC | Brier | 보정 기울기 |
  |---|---|---|---|
  | RandomForest | 0.783 | 0.074 | 1.11 |
  | 로지스틱 회귀 | 0.781 | 0.075 | 1.04 |
  | 로지스틱 회귀 + 나이 스플라인 | 0.781 | 0.075 | 1.05 |
  | XGBoost | 0.774 | 0.075 | 0.86 |
  | ExtraTrees (기존 모델 일부) | 0.773 | 0.076 | 1.57 |
  | HistGradientBoosting | 0.771 | 0.075 | 0.84 |
  | LightGBM | 0.768 | 0.076 | 0.79 |

  질환별 로지스틱 회귀 대비 RandomForest의 차이는 −0.011~+0.011로 방향이 엇갈렸다. 최종 판단은 5.3의 모델 비교로 한다.

### 4.2 나이 스플라인(실험 후 결정)

로지스틱 회귀는 나이를 직선으로 다룬다. 그래서 젊은 여성에서 과대예측이 보였다(20대 여성 당뇨 실제 0.4%, 예측 1.4%). 나이에 `SplineTransformer(n_knots=4, degree=3)`를 적용한 버전을 5.1의 중첩 교차검증으로 비교한다. **25–44세에서 Brier가 낮아지고 AUROC가 떨어지지 않을 때만** 채택한다.

### 4.3 등급 기준값

1. 19–59세 학습 데이터로 5-fold 층화 교차검증 예측값(OOF)을 만든다.
2. 그중 25–44세 행만 골라 질환별로 계산한다.
   - `thresh_medium`: Youden J(민감도 + 특이도 − 1)가 최대인 확률값
   - `thresh_high`: 25–44세 음성 예측값의 95번째 백분위
3. `thresh_high <= thresh_medium`이면 학습을 실패로 처리한다.
4. 19–59세 전체로 최종 모델을 다시 학습한다.

등급은 `p >= thresh_high`이면 high, `p >= thresh_medium`이면 medium, 그 밖은 low다.

**기각한 대안**

| 방식 | 문제 |
|---|---|
| 전 질환 고정 10%/30% | 40세 이상에서 사실상 전원이 높음(60세 이상 고혈압 89%, 특이도 0%). 30대 당뇨는 민감도 21% |
| 전 연령 Youden | 30대의 98~99%가 낮음(30대 고혈압 민감도 8%) |
| 또래 평균 대비 등급 | 상대 위험이 과장되어 보일 수 있다. 젊은 사람의 위험이 낮은 것은 정상이다 |

30대 평가에서 25–44세 맞춤 기준의 Youden J는 고혈압 0.51, 당뇨 0.50, 고콜레스테롤 0.31, 고중성지방 0.48이었다. 이는 비중첩 수치라 낙관적이며, 최종 수치는 5.1의 중첩 교차검증으로 낸다.

```python
    "thresh_high": float,
    "meta": {"data": "KNHANES 2022-2024", "train_age": [19, 59],
             "threshold_age": [25, 44], "n_train": int, "n_pos": int,
             "sklearn": "1.8.0", "trained_at": "ISO 8601"},
}
```

- 변수 이름은 앱 필드 이름을 쓴다. 서비스 코드에서 이름을 바꾸는 단계를 없애기 위해서다.
- `feat_kor`의 "BMI"와 "체지방률"은 `trend_service._FEATURE_MAP`과 같은 글자여야 한다. 그래야 추세의 `is_shap_important`가 동작한다.
- pkl에 학습 데이터 행을 넣지 않는다. 표본 수와 평균만 넣는다.

### 4.5 코드 구성

| 파일 | 역할 |
|---|---|
| `training/features.py` | KNHANES → 라벨·입력 변환(`build_labels`, `build_features`), 기준값 선택(`choose_thresholds`). 학습과 평가가 같이 쓴다 |
| `training/train.py` | 4.1~4.4를 실행해 `models/*.pkl` 4개를 쓰고 기준값·표본 수를 출력한다 |
| `training/evaluate.py` | 5절 평가를 실행해 보고서를 쓴다 |
| `training/analysis/common.py` | 기존 KNHANES 로더를 재사용한다 |
| 삭제 | `training/retrain_final.py`, 기존 `models/*.pkl` 7개 |

`training/train_models.py`(이전 비교 실험)는 기록용으로 남긴다.

## 5. 평가

### 5.1 주 평가: 25–44세 중첩 교차검증

```
바깥 5-fold (19–59세, 층화)
  학습 4/5: 모델 학습 + 안쪽 5-fold OOF로 25–44세 기준값 결정
  평가 1/5: 예측 → 25–44세 행만 지표 계산
바깥 5개 평가 예측을 모아 지표를 낸다
```

| 관점 | 지표 | 불확실성 |
|---|---|---|
| 판별 | AUROC | 부트스트랩 1,000회 95% CI |
| 보정 | Brier, 예측 평균 vs 실제 유병률, 보정 기울기·절편, 10분위 보정 곡선 | 95% CI |
| 등급 | 등급별 인원 비율과 실제 유병률, 보통 기준의 민감도·특이도, 높음 등급의 양성 적중률 | 95% CI |

하위군 25–34세, 35–44세, 남, 여를 따로 보고하고 양성 수를 함께 적는다. 민감도는 특이도 없이 단독으로 보고하지 않는다.

### 5.2 비교 기준선

| 기준선 | 목적 |
|---|---|
| 나이 + 성별 로지스틱 회귀 | 결과지·가족력이 나이 외에 더하는 정보. AUROC 차이를 대응 부트스트랩 CI로 보고한다 |
| 기존 배포 모델 | 새 라벨로 평가한다. 전체 데이터로 학습한 모델이라 낙관적이라는 점을 명시한다 |

### 5.3 보조 평가

| 평가 | 방법 | 한계 |
|---|---|---|
| 시간 검증 | 2022–23년(19–59세) 학습 → 2024년 평가 | 2024년은 40–59세뿐이다 |
| 외부: NHANES 2003–04 | 가족력을 뺀 모델(나이, 성별, BMI, 체지방률)을 KNHANES 19–59세로 학습한다. 20–49세에서 4개 질환의 AUROC와 예측 평균 vs 실제를 본다. 라벨은 KNHANES 정의에 맞춘 `training/analysis/nhanes_check.py`를 따른다 | 미국인, Xitron 기기, 당뇨 양성 76명 |
| 외부: Kaggle 국민체력100 | 같은 가족력 제외 모델로 고혈압(측정 140/90 이상) AUROC만 본다 | 단회 측정이라 고혈압 비율이 KNHANES의 3~10배다. 보정은 평가하지 않는다 |
| 나이 스플라인 | 4.2의 규칙으로 채택 여부를 정한다 | |
| 모델 비교 | 로지스틱 회귀, 로지스틱 회귀 + 나이 스플라인, RandomForest, XGBoost를 5.1과 같은 중첩 교차검증(기준값 결정 포함)으로 돌린다. 로지스틱 회귀 대비 AUROC·Brier 차이와 대응 부트스트랩 95% CI, 보정 기울기를 보고한다 | |

**모델 선정 규칙(사전 고정)**: 다른 모델의 AUROC 차이 CI가 0을 포함하면 로지스틱 회귀를 유지한다. CI 하한이 0보다 크면(유의하게 더 좋으면) 그 모델을 질환별로 검토한다. 이때 4.1의 보정·설명 기준과 보정 단계 추가 비용을 함께 판단하며, 별도 논의로 결정한다.

### 5.4 통과 기준 (사전 고정)

질환별로 다음을 모두 만족해야 배포한다.

1. **보정**: 25–44세에서 예측 평균이 실제 유병률의 95% CI 안에 있고, 보정 기울기가 0.8~1.2다.
2. **기여**: AUROC가 나이 + 성별 모델보다 낮지 않다(차이의 점추정 ≥ 0).
3. **등급**: `thresh_high > thresh_medium`이고, 실제 유병률이 low < medium < high 순서다.

통과하지 못한 질환은 배포하지 않는다. 원인과 대안(재보정 등)을 보고서에 적고 별도로 논의한다. AUROC 목표 수치는 두지 않는다.

## 6. 서비스 반영

### 6.1 `prediction_service.predict_all`

시그니처 `predict_all(inbody: dict, user_profile: dict) -> list[dict]`와 출력 형식을 유지한다.

```python
{"disease": "고혈압", "probability": 0.083, "risk_level": "low",
 "top_factors": [{"feature_kor": "BMI", "value": 27.1,
                  "shap_value": 0.41, "direction": "up"}, ...]}
```

**입력 구성과 예외**

| 상황 | 처리 |
|---|---|
| `gender` 없음 | `ValueError` → 400 (기존과 같다) |
| `birth_year` 없음 | `ValueError` → 400 |
| 나이 19세 미만 | `ValueError("성인만 예측할 수 있습니다")` → 400 |
| 나이 60세 이상 | 예측한다. 학습 범위·타겟 밖이라는 점은 이 문서에만 기록한다 |
| `bmi` 또는 `body_fat_percentage` 없음 | 모든 질환을 건너뛴다 → 빈 리스트 → 호출부가 422 (기존과 같다) |
| `fh_*` 없음 또는 `null` | 0 |
| BMI가 12–60, 체지방률이 3–70을 벗어남 | `ValueError` → 400. OCR 오독으로 본다. 범위는 KNHANES 19–59세 실제 범위(BMI 14.5–48.0, 체지방률 6.7–54.6)에 여유를 둔 값이다 |
| 사용할 모델이 하나도 없음 | `ModelBundleError` → 500 |

**기여 요인**
- 입력 `x`를 파이프라인의 변환 단계로 바꿔 `z`를 만든다.
- 열별 기여 `c = coef * (z - background)`를 계산하고, `feature_groups`로 원래 변수 단위로 합친다.
- 로지스틱 회귀에서 이 값은 SHAP 값과 같다. 그래서 필드 이름 `shap_value`를 유지한다.
- 성별, 사용자가 답하지 않은(`None`·없음) 가족력, 다른 질환의 가족력을 빼고 |기여|가 큰 순서로 3개를 반환한다. 이 변수들은 예측에는 그대로 쓴다. 답하지 않은 정보로 설명하지 않고, 다른 질환 가족력은 계수 방향이 상식과 어긋날 수 있어서 뺀다(질환별 가족력: 고혈압→고혈압, 당뇨→당뇨, 고콜레스테롤·고중성지방→고지혈증). `direction`은 기여가 양수면 "up"이다.

**불러오기**
- 처음 호출할 때 `models/{disease_key}.pkl`을 불러와 캐시한다. 다른 이름의 파일(예: 기존 `hypertension_male.pkl`)은 무시한다.
- 파일이 없는 질환은 경고 로그를 남기고 건너뛴다. 5.4를 통과하지 못해 배포하지 않은 질환이 이 경우다.
- `version != 2`이거나 `features`가 코드의 기대 목록과 다르면 즉시 예외를 던진다.
- 앱 시작 시(`main.py` lifespan) `load_models()`로 미리 불러온다. 형식 오류가 첫 사용자 요청이 아니라 배포 단계에서 드러나게 하기 위해서다.

**삭제**
- `shap` 불러오기와 matplotlib 캐시 우회 코드를 지운다.
- `_patch_sklearn_compat`과 성별별 파일 선택 로직을 지운다.
- 서버 `requirements.txt`에서 `shap`, `imbalanced-learn`을 뺀다(이 파일에서만 쓰였다).
- `scikit-learn==1.8.0`으로 고정한다.

- 저장된 `ai_report`: 형식이 같아서 그대로 표시된다.
- **RAG**: 요인 이름이 "나이", "BMI", "체지방률", "고혈압/당뇨/고지혈증 가족력"으로 바뀐다. RAG 용어집 `FEATURES`에 매핑을 추가해야 한다(RAG 작업 목록으로 넘긴다).

## 8. 배포 순서

1. `python training/train.py` → `python training/evaluate.py` → 5.4 통과 여부를 확인한다.
2. 통과한 질환만 `python -m training.train --only ...`으로 저장한다. 그 pkl과 평가 보고서를 커밋하고, 기존 pkl 7개와 `retrain_final.py`를 삭제한다. 통과하지 못한 질환은 `models/`에 파일이 남지 않게 한다.
3. `prediction_service`를 교체하고 테스트를 통과시킨다.
4. `back` 브랜치에 push한다 → Railway에 배포된다.

기존 pkl의 Git 이력에 남은 데이터 행은 저장소가 비공개인 동안 그대로 둔다. 공개 전에 이력 정리 여부를 결정한다.

## 9. 위험과 한계

- **타겟 연령의 양성 수가 적다.** 30대 당뇨 양성이 29명이다. 그래서 주 평가를 25–44세(당뇨 양성 101명)로 하고 신뢰구간을 함께 낸다.
- **단면 자료다.** "현재 유병일 확률"이지 미래 발병 위험이 아니다. 리포트 문구가 이를 넘지 않아야 한다.
- **기기 차이.** KNHANES는 InBody 970, 앱은 InBody 270이다. 체지방률 산출 방식 차이는 검증하지 못했다.
- **가족력 회상 편향.** 진단받은 사람이 가족력을 더 잘 기억할 수 있다.
- **③ 전까지는 가족력이 항상 0이다.** 그동안 가족력이 있는 사용자는 위험이 과소평가된다.
- **체지방률의 추가 기여가 작다.** 고혈압·당뇨에서는 BMI와 같은 수준이다. "인바디가 BMI보다 낫다"는 주장은 하지 않는다.
