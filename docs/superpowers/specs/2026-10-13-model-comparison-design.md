# 위험 예측 방식 비교실험 (규칙표 · ML · LLM)

- 작성일: 2026-10-13
- 상태: 검토 대기
- 범위: `training/compare.py`(비교 실행·보고서), `tests/risk_model/test_compare.py`(테스트 추가)
- 범위 밖: 배포 모델·`prediction_service` 변경, LLM 리포트(RAG) 품질 평가

## 1. 배경과 목표

계획 발표에서 받은 지적은 두 가지다.

1. "표나 수식으로 보면 되는데 왜 학습한 모델이 필요한가"
2. "ChatGPT에 수치를 넣고 물어보는 것보다 무엇이 나은가. 정량적으로 보여라." LLM은 같은 입력에도 매번 다른 퍼센트를 낸다는 지적이 함께 있었다.

서비스 구조는 이렇다. 위험 확률은 ML 모델이 결정적으로 계산하고, LLM은 기여 요인을 받아 설명만 한다. 이 실험은 그 구조가 맞다는 근거를 만든다.

**목표**: 배포 중인 로지스틱 모델(`2026-10-12-risk-model-redesign-design.md`)을 다음 둘과 같은 사람, 같은 입력으로 비교한다.
- 규칙표(체크리스트 점수)
- GPT 제로샷

**발표용 산출물**
- 질환 4개 × 모델 5개의 AUROC 표 1장
- LLM 출력 편차 그림 1장

**비목표**
- 새 모델을 학습하거나 배포 모델을 바꾸는 일
- 프롬프트 엔지니어링으로 LLM 성능을 최대로 끌어올리는 일. 프롬프트는 1개로 고정한다(6절).
- 미진단자 코호트, 측정치 라벨 같은 다른 실험 설계(2.2절)

## 2. 결정 사항

### 2.1 요약

| 항목 | 결정 |
|---|---|
| 코호트·라벨·입력 | 배포 모델과 같다. `training_rows`(19–59세, BIA 측정, 라벨 `HE_HP==4` 등, 입력 7개)를 쓴다 |
| 평가 대상 | 25–44세 전원. 질환별로 라벨이 있는 사람이다 |
| 질환 | 고혈압, 당뇨, 고콜레스테롤, 고중성지방 |
| 비교 모델 | ⓪ 나이+성별 로지스틱, ① 체크리스트 점수, ② 배포 로지스틱, ③ XGBoost, ④ GPT 제로샷(Codex CLI, `gpt-5.6-luna`) |
| ML 예측 | 기존 바깥 5-fold 예측을 그대로 쓴다. 평가 대상인 사람은 학습에 들어가지 않는다 |
| LLM | Codex CLI(`codex exec`, ChatGPT 계정 로그인), `gpt-5.6-luna`, reasoning low, 출력 스키마 지정 |
| 반복 측정 | 25–44세에서 무작위로 300명을 뽑아 1인당 5회 호출한다 |

### 2.2 핸드오프 문서와 달라진 점과 이유

| 핸드오프 | 이 설계 | 이유 |
|---|---|---|
| 2022–23 학습, 2024 테스트 | 기존 중첩 CV(25–44세 평가) | 2024년 체성분검사는 40세 이상만 했다(4,206명, 최소 40세). 시간 기준으로 나누면 타겟인 30대가 테스트셋에 0명이다 |
| 미진단자 + 측정치 라벨 | 배포 모델 라벨(치료 중인 환자 포함) | 발표에서 방어할 대상은 실제로 배포한 모델이다 |
| 세트 A/B(흡연·음주·활동 포함) | 배포 입력 7개 | 생활습관은 재설계 때 역인과 때문에 기각했다(재설계 spec 3.4) |
| BIA 17개 중 결과지 항목 | BMI·체지방률 | InBody 270으로 확정됐다(재설계 spec 3.4) |
| LightGBM | 기존 XGBoost | 트리 모델 비교는 이미 했다. XGB는 25–44세 AUROC가 LR보다 0.003–0.017 낮았다 |
| 질환 3개 | 4개 | 배포 모델이 4개다. 질환을 추가해도 LLM 호출 수는 늘지 않는다(한 번 호출로 4개를 받는다) |
| LLM 300–500명 샘플로 AUROC | 25–44세 전원으로 AUROC | 400명이면 당뇨 양성이 약 14명이라 신뢰구간이 쓸 수 없을 만큼 넓다 |
| DeLong 검정 | 짝지은 부트스트랩 차이 CI | 기존 보고서와 방식이 같다. 같은 질문에 답한다 |

## 3. 비교 모델

| | 모델 | 예측값 | 구현 |
|---|---|---|---|
| ⓪ | 로지스틱(나이·성별) | 확률 | `evaluate.outer_predictions(X[["age","female"]], ...)` |
| ① | 체크리스트 점수 | 0–4 정수 | 아래 규칙. 학습하지 않는다 |
| ② | 배포 로지스틱 | 확률 + 등급 | `evaluate.nested_predictions`. 고콜레스테롤만 나이 스플라인(배포와 같다) |
| ③ | XGBoost | 확률 | `evaluate.outer_predictions(X, y, COMPARE_MODELS["xgb"])` |
| ④ | GPT 제로샷(`gpt-5.6-luna`) | 0–100 → 확률 | 4절 |

**① 체크리스트 점수** 다음 항목에 해당하면 각각 1점이다.
- BMI 25 이상(대한비만학회 비만 기준)
- 체지방률 남 25% 이상, 여 30% 이상
- 해당 질환의 가족력(고혈압→`fh_hypertension`, 당뇨→`fh_diabetes`, 고콜레스테롤·고중성지방→`fh_dyslipidemia`)
- 나이 40세 이상

이 규칙은 "표로 보면 된다"는 방식을 같은 입력으로 공정하게 재현한 것이다. 점수가 정수라 동점이 많지만, AUROC는 동점을 0.5로 처리하므로 그대로 계산한다.

## 4. LLM(④)

### 4.1 호출

- 사람 1명당 1회 호출해 질환 4개의 확률을 함께 받는다.
- 대상은 4개 질환 중 하나라도 평가 대상(25–44세, 라벨·입력 있음)인 사람 전원이다(약 2,900명).
- 질환별 AUROC는 그 질환의 라벨이 있는 사람만으로 계산한다.
- API 키 대신 Codex CLI를 subprocess로 호출한다. 사용자의 ChatGPT 계정 로그인을 쓴다.
  `codex exec --ignore-user-config -m gpt-5.6-luna -c model_reasoning_effort=low -s read-only --skip-git-repo-check --ephemeral --output-schema <스키마> -o <출력파일> "<프롬프트>" < /dev/null`
  - `--ignore-user-config`: 사용자 플러그인, hook, 알림 설정이 섞이지 않게 한다.
  - 작업 폴더는 빈 임시 폴더로 둔다. 레포 파일이 컨텍스트에 들어가지 않게 하기 위해서다.
  - stdin을 닫는다. 닫지 않으면 입력을 기다리며 멈춘다(2026-10-13 확인).
- 모델 선정(2026-10-13, 가상 프로필 1건으로 실측).
  - `gpt-5-mini`, `gpt-5.4-mini`: ChatGPT 계정에서 지원하지 않는다.
  - 기본 모델 `gpt-6.1-sol`(high): 55초가 걸렸고 `-1`을 반환해 답을 거부했다. 이후에는 용량 초과 오류가 났다.
  - `gpt-5.6-luna`(low): 8초, 호출당 약 2.3만 토큰. 대부분 Codex 에이전트의 시스템 프롬프트다.
  - `gpt-5.6-terra`(low): 21초, 약 2.6만 토큰.
  - 속도와 한도 소모를 고려해 luna를 쓴다.
- 샘플링 설정(temperature 등)은 기본값이다. 일반 사용자가 묻는 조건과 같다.
- 출력 스키마(JSON)의 키는 `hypertension`, `diabetes`, `cholesterol`, `triglyceride`이고, 값은 0–100 정수다(`minimum`·`maximum` 지정).
- 동시에 4개씩 호출한다(전체 약 2–3시간).
- 반복 측정: 무작위로 뽑은 300명(`random_state=42`)에게 4회 더 호출해 1인당 5회를 채운다. AUROC에는 1회차 응답만 쓴다.
- 총 호출 수는 약 2,900 + 1,200 = 4,100회다.

### 4.2 캐시와 실패 처리

- 응답은 `training/output/llm/gpt-5.6-luna.jsonl`에 한 줄씩 쌓는다. 키는 `(행 인덱스, 반복 번호)`이다. `training/output/`은 gitignore 대상이다.
- 다시 실행하면 캐시에 있는 키는 건너뛴다. 중간에 끊겨도 이어서 실행할 수 있다.
- 호출이나 파싱에 실패하면 3회 재시도한다. 용량 초과 오류는 30초 간격으로 재시도한다. 그래도 실패하면 그 행을 결측으로 기록하고 보고서에 실패 수를 적는다. 평가에서는 그 사람을 모든 모델에서 뺀다. 같은 사람끼리 비교해야 하기 때문이다.
- `--limit N` 옵션으로 앞의 N명만 호출한다. 시범 실행용이다.
- Codex 로그인 정보는 CLI가 관리한다. 코드에서는 읽거나 기록하지 않는다.

### 4.3 데이터 전송

KNHANES 참가자의 입력 7개(나이, 성별, BMI, 체지방률, 가족력 3개)를 Codex CLI를 거쳐 OpenAI로 보낸다. ID, 조사연도, 라벨은 보내지 않는다. 이용약관상 외부 전송이 허용되는지는 사용자가 판단했다(2026-10-13). 보고서 한계 절에 이 사실을 적는다.

## 5. 지표

모든 지표는 25–44세에서 질환별로 계산한다. 계산 대상은 다섯 모델의 예측이 모두 있는 사람이다.

| 지표 | 방법 |
|---|---|
| AUROC | `bootstrap_ci`(1,000회) |
| AUROC 차이 | ② 대비 `paired_diff_ci` |
| AUPRC | `average_precision_score` + `bootstrap_ci` |
| Brier, 평균 예측 vs 실제 | 확률 모델(⓪②③④)만. ①은 확률이 아니라서 "해당 없음"으로 적는다 |
| 같은 특이도에서의 민감도 | ②의 '보통 이상' 판정의 특이도를 기준으로 한다. 다른 모델마다 이 특이도 이상이 되는 가장 낮은 기준값을 찾고, 그 지점의 민감도를 Wilson CI와 함께 보고한다 |
| 하위군 | 25–34세, 35–44세의 AUROC(CI). 양성이 10명 미만인 칸은 "표본 부족"으로 적는다 |

**LLM 편차 지표**(300명 × 5회, 질환별)
- 사람별 5회 응답의 표준편차(%p): 중앙값, 90번째 백분위
- 사람별 최대–최소 범위(%p): 중앙값, 최대
- **판정이 바뀌는 비율**: 위 "같은 특이도" 기준값으로 5회 응답을 판정했을 때, 양성과 음성이 섞여 나온 사람의 비율. ML은 결정적이라 편차와 판정 변경이 모두 0이다.

## 6. 프롬프트

시스템 메시지와 사용자 메시지를 고정한다. 보고서 부록에 원문을 그대로 싣는다.

- 역할: "당신은 의료 위험도를 추정하는 도우미입니다."
- 입력 표기 예:
  - 나이 34세, 남성, BMI 26.1, 체지방률 27.4%
  - 고혈압 가족력 있음, 당뇨 가족력 없음, 고지혈증 가족력 없음
- 질환 정의: 재설계 spec 3.2의 라벨 정의를 그대로 쓴다.
  - 고혈압: 측정 혈압 140/90mmHg 이상 또는 혈압약 복용
  - 당뇨: 공복혈당 126mg/dL 이상, 당화혈색소 6.5% 이상, 의사 진단, 또는 약·인슐린 치료
  - 고콜레스테롤: 총콜레스테롤 240mg/dL 이상 또는 약 복용
  - 고중성지방: 12시간 이상 공복 상태에서 중성지방 200mg/dL 이상
- 질문: "이 사람이 **현재** 각 질환에 해당할 확률을 0–100 정수로 답하세요."
- 같은 정의를 쓰기 때문에, LLM과 ML이 같은 대상을 예측한다.

**편차 그림**: 질환별 패널 4개로 구성한다. 300명 중 무작위 40명을 x축에 ② 예측값 순서로 놓는다. 각 사람마다 GPT 5회 응답을 점으로 찍고 범위를 세로선으로 그린다. ② 예측값은 하나의 마커로 겹쳐 그린다. "같은 사람인데 GPT는 매번 다르고 ML은 한 점"이라는 사실이 그림 한 장으로 보이게 하는 것이 목적이다.

`--skip-llm`으로 실행하면 ⓪①②③만 계산하고 ④ 열은 비운다(1단계).

## 8. 진행 순서

각 단계가 끝나면 멈추고 결과를 보고한다.

1. **⓪①②③ 표**: `--skip-llm`. LLM을 호출하지 않는다. ②③ 수치가 기존 평가 보고서와 같은지 확인한다(AUROC 차이 0.002 이내).
2. **LLM 시범 호출**: `--limit 20`. 파싱 성공률, 응답 분포, 호출당 시간·토큰, 그리고 Codex 5시간·주간 한도가 몇 % 줄었는지 보고한다. 이 값으로 전체 실행이 한도 안에 들어가는지 추정한다. 들어가지 않으면 AUROC 대상을 줄이거나 묶음 호출로 바꿀지 사용자와 다시 정한다.
3. **전체 실행**: LLM 약 4,100회 호출 → 표와 편차 그림을 만든다.
4. **보고서 정리**: 발표용 표 1장과 그림 1장을 확정한다.

## 9. 테스트

`tests/risk_model/test_compare.py`를 새로 만든다.
- `checklist_score`: 경계값을 확인한다(BMI 25.0 → 1점, 체지방률 남 25.0·여 29.9, 나이 40, 질환별 가족력 매핑).
- LLM 응답 파싱: 정상 JSON → 확률 0–1. 키 누락이나 범위 밖 값 → 실패로 처리한다.
- 같은 특이도 기준값: 작은 배열에서 기대한 기준값과 민감도가 나오는지 확인한다.

CLI 호출은 테스트하지 않는다. 시범 실행(8절 2단계)이 그 확인을 대신한다.

## 10. 위험과 한계

- **프롬프트 의존성.** LLM 성능은 프롬프트에 따라 달라진다. 이 실험은 "같은 정보로 일반적인 질문을 했을 때"를 측정한다. LLM의 상한을 측정하는 실험이 아니다.
- **LLM이 공개 지식으로 유병률을 추론할 수 있다.** 이 경우 AUROC가 ②와 비슷하게 나올 수 있다. 그렇게 나와도 편차와 보정(Brier, 평균 예측)으로 차이를 보인다. 결과는 나온 그대로 보고한다.
- **단면 자료.** 비교 대상은 "현재 유병일 확률"이다. 미래 발병 예측력을 비교하는 실험이 아니다.
- **데이터 외부 전송.** 4.3절.
