# 리포트 근거 정확도 평가: RAG vs 단순 프롬프트

## 왜

발표에서 "RAG를 붙여 리포트가 근거에 기대게 됐다"를 수치로 보여준다. 사용자가 고른 지표는 둘이다.

1. **근거 인용률** — 리포트의 의학 주장 중 출처(S번호)가 달린 비율
2. **근거 없는 주장 비율** — 의학 주장 중 코퍼스 문서로 뒷받침되지 않는 비율

두 버전의 주장을 같은 기준으로 판정해야 공정하다. 그래서 주장마다 코퍼스 전체에서 관련 문단을 검색해 와서
판정한다(사용자 결정). 단순 프롬프트가 지침과 맞는 말을 했으면 "뒷받침됨"으로 정당하게 센다.

## 목표 / 비목표 / 반목표

- 목표: 같은 10명에 대해 두 버전 리포트를 만들고, 의학 주장 단위로 판정해 두 지표와 예시 문장을 낸다.
- 비목표: 앱 리포트 파이프라인 수정, 사람이 만든 정답 라벨, 통계 검정(n=10이라 건수와 비율만 보고).
- 반목표(기술적으로 돌아가도 실패):
  - 기준 버전을 약하게 만들어 차이를 부풀리는 것(다른 모델, 낮은 추론 설정).
  - 사용자 수치 해석("체지방률 39.8%")을 근거 없는 주장으로 세는 것.
  - 판정기가 어느 버전의 주장인지 알고 판정하는 것.

## 대상

- KNHANES 5명(`report_preview._cases()`)과 합성 부위 5명(`_synthetic_cases()`), 총 10명.
- 내 인바디는 넣지 않는다(발표 수치는 공개 데이터로만). — 내 판단

## 두 버전

| | 단순 프롬프트 | RAG |
|---|---|---|
| 모델 | gpt-6.1-terra, reasoning low | 같음 |
| 시스템 프롬프트·지침 | 현재 프롬프트에서 근거·인용 문장만 뺀 것 | 현재 `ai_service` 그대로 |
| 입력 | 인바디, 프로필, 위험도·SHAP, personal_metrics | 같음 + [근거] |
| 후처리 | 없음(source_ids는 비운다) | `validate_citations` |
| 출력 형식 | `AIReportContent` | 같음 |

기준은 "지금 프롬프트에서 RAG만 뺀 것"이다(사용자 결정, B안). 차이가 RAG에서만 생기게 하려는 것이다.
- 뺄 문장: `_REPORT_SYSTEM_INSTRUCTION`과 `_REPORT_GUIDE`를 문장 단위로 나눠 "근거", "S번호", "source_ids",
  "직전 리포트"가 들어간 문장을 뺀다. 나머지 규칙(표현 안전, personal_metrics 사용, 항목 수 등)은 그대로 둔다.
  현재 프롬프트에서 자동으로 만들어 앱 프롬프트가 바뀌어도 따라가게 한다.
- 실제로 쓴 기준 프롬프트 전문을 결과 폴더에 저장해 발표 때 보여줄 수 있게 한다.
- RAG 이전 프롬프트(커밋 `57bfe0c`)와의 비교는 하지 않는다.

RAG 리포트는 평가 스크립트가 새로 만든다. 인용된 근거의 본문(chunk_id)까지 저장해야 하기 때문이다. — 내 판단

## 판정 흐름

리포트 1건마다:

1. **주장 추출 (GPT 1회)** — 리포트의 문장 필드(summary, watch_points, risk_report.message,
   lifestyle_plan reason·actions, supplement_candidates)를 항목 id와 함께 넘기고, 원자 주장 목록을 받는다.
   각 주장은 `kind`: `medical`(기준값, 권장량, 운동·식사 권고, 효과) / `user_data`(사용자 수치·위험도·SHAP 해석) /
   `other`(면책, 상담 권유). 지표는 `medical`만 센다.
2. **주장별 코퍼스 검색** — 주장 문장을 임베딩해 `match_rag_chunks`로 상위 5개(유사도 하한 없음)를 받는다.
   두 버전 모두 이 5개만 후보로 쓴다(같은 조건). — 내 판단
3. **뒷받침 판정 (GPT 1회)** — 주장마다 후보 문단을 보고 `supported` / `contradicted` / `not_found`,
   그리고 뒷받침한 문단 id 목록을 받는다. 판정 프롬프트에는 버전 정보를 넣지 않는다.
4. **인용 판정 (RAG만, GPT 1회)** — 인용된 `medical` 주장마다 그 항목이 인용한 청크만 보여주고 같은 3분류로 판정한다.
   코퍼스 판정과 따로 해서 RAG 쪽 후보가 늘어나는 불공정을 막는다. — 내 판단

주장 쪼개기 규칙 — 내 판단:
- 사용자 수치와 기준값이 섞인 문장은 쪼갠다. "체지방률 39.8%"는 `user_data`, "기준 25%"는 `medical`.
- personal_metrics에서 코드가 계산한 개인 목표("정상 BMI까지 8.7 kg")는 `user_data`.

판정기는 GPT(Codex CLI, 기존 `rag/eval/judge.codex_ask` 방식). Gemini는 쓰지 않는다.

## 지표

- 근거 인용률 = 소속 항목에 유효한 source_ids가 있는 `medical` 주장 / 인용 칸(source_ids)이 있는 항목의 `medical` 주장.
  summary처럼 인용 칸이 없는 필드의 주장은 인용률에서 빼고, 근거 없는 주장 비율에는 넣는다. — 내 판단
  단순 프롬프트는 인용할 근거가 없어 구조상 0%이고, 리포트에 그렇게 밝힌다.
- 근거 없는 주장 비율 = `contradicted` + `not_found` / `medical` 주장. `contradicted`는 따로도 보고한다.
- 인용 정확도(RAG만) = 인용된 `medical` 주장 중 4단계에서 `supported`인 비율.
  처음 요청한 "근거 정확도"에 가장 가까운 숫자라 같이 낸다. — 내 판단

## 산출물

- 코드: `rag/eval/grounding.py` (`run`, `judge`, `summarize` 서브커맨드), 테스트 `tests/rag/test_grounding.py`.
- 결과: `rag/eval/preview/grounding/`(gitignore). 리포트 원본, 주장별 판정 JSONL, `summary.md`.
- `summary.md`: 두 버전 지표 표(건수와 비율), 사례별 표, 발표용 예시 3쌍
  (단순 프롬프트의 근거 없는 주장 ↔ 같은 사람 RAG 리포트의 인용된 주장).

## 제약

- Gemini 임베딩 무료 등급: 분당 100건, 하루 1000건. 주장 약 300~400개라 분당 한도에 맞춰 쉬어 간다.
- 실행은 중간에 끊겨도 이어서 할 수 있게 리포트·판정을 단계별로 저장한다(`report_preview.run`과 같은 방식).
- 키는 `.env`에서만 읽는다. 개인 데이터와 결과 파일은 커밋하지 않는다.
